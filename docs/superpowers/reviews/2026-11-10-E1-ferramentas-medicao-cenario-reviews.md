## Concerns (transcritos como registrados)

### T2
1) The plan does not say whether `total` includes the main context. I defined `total` as the sum of the agent roles only, and `main` is reported separately with its own tokens and cost. `total.calls` also counts agents only, as the plan says. If Task 3 or later wants `total` to include the main context, this needs a one-line change. 2) The plan does not define the shape of the `runs` (Attempts) parameter. I accept an array of {run, sessions} or an object {run: {sessions}}, and only Task 11 will confirm that shape. 3) `reviewRounds` and `tasks` come back as empty defaults, and every agent gets the provisional role `agent:<agentType ?? 'general'>`. Task 3 will replace both. 4) In the main context, `agentCalls` counts each Agent/Task tool_use once by its `tool_use` id, so streamed duplicate lines do not inflate it. 5) The agent `meta` and `workflow` fields are read but not yet used in the output, because Task 3 needs them. 6) The fixtures were generated by a throwaway script that I deleted. They follow the plan's constraints: UUIDs in the 00000000-0000-4000-8000-xxxxxxxxxxxx range, agent ids agent-afab01 and agent-afab02, and every free-text field starting with [fab].
