# § 14. Events from plan-coordinator

`plan-coordinator` invokes this skill once with "plan completed" after the run finishes (a caller may also pass "wave N closed" mid-run), when `progress.json` has `plan.roadmap` set to the folder.

1. Locate the `progress.json` (the one the caller names; otherwise the one in the plan folder, `docs/plans/<topic>/`) and run `node "${CLAUDE_SKILL_DIR}/scripts/roadmap.mjs" close-from-state "<folder>" --state <progress.json> --json`, then follow the rest of the event (`now`, `inflight-add`, § 9). Never edit the state. An old `progress-*.md` falls under the artifact rule (position 3 from the plan).
2. `close-from-state` decides and records; do not decide or record the same pieces again by hand (no second `set-status`, evidence or `log` row). Read its JSON: `decision` `closed` means plan completed and final gate passed, and it already set the on-branch word, wrote the evidence (the state path plus the commit SHAs it verified with `git cat-file --batch-check`) and added the `log` row; `not-closed` only lifts the status to the plan word and never lowers it (`reasons` says why). Never infer the integrated word (position 6) without a SHA that is on the integration branch.
3. On a refusal (`deliverable-unknown`, `roadmap-mismatch`, `state-schema`, `git-unavailable`), nothing was written: find the deliverable (the panel row whose Evidence or Next step cites that plan, else the `E<n>` the plan's title names) and fix the cause, else ask once. When the event says `no questions`, never ask: write each unanswered question as a `pending` item (`node "${CLAUDE_SKILL_DIR}/scripts/roadmap.mjs" add-pending "<folder>" --owner user --text "<question>"`) and list them under `Pending for the user:` in the Step 7 hand-back.
4. Read the current branch with `git branch --show-current` and keep its "in flight" row `live` (`node "${CLAUDE_SKILL_DIR}/scripts/roadmap.mjs" inflight-add "<folder>" <branch>`; a no-op when already live).
5. Ask the user only for what the state cannot tell, such as an integration SHA (a plan that completed on a branch is `on-branch`, not integrated). With `no questions`, use `add-pending` as in item 3.
6. If a piece or the deliverable closed, run the end-of-piece check (§ 9). Hand back to plan-coordinator with the Step 7 report (keeping pending items for its final report).
