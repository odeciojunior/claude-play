# § 1. Decision

**When:** the user, a meeting note or a source settles a choice.

1. `decisions.md`: append one row per choice (two choices, two rows).
   - ID: `node "${CLAUDE_SKILL_DIR}/scripts/roadmap.mjs" next-id "<folder>" DEC`. Date: decision day. Deliverable: `E<n>` or `-`.
   - Decision: what was chosen, one sentence. Discarded alternative: what was not chosen; if nobody stated one, `none stated`, never invented.
   - **Contradicts:** classify with `references/rubric-contradiction.md` and write the cell it gives: the strategy section, `-`, or the `DEC` ID. Unsure: its `incerto` rule.
   - Revisit when: a condition ("the owner reprioritizes sharing"), not a date unless one was supplied; nobody supplied one: `-`, never invented.
   - Origin: `user`, `executor`, `SRC-NN` or `REQ-NNN`. Status: `vocab.decisionInForce`, or `vocab.decisionPending` while awaiting someone. Cells: `formats.md § 6`; the CLI does not append rows of Origin `user`, so this is an edit.
   - A row may cite the `BLQ-n` it closes (retired ids are fine); apply § 5 "Closed" for the blocker.
2. **Supersedes an earlier decision?** Only when the new decision replaces the old one's choice on the same question (the old Decision would now be answered differently). Touching the same deliverable or making the old choice moot is not enough. Unsure: ask, recommending "not superseded". When it does supersede, set the old row's Status to `<vocab.decisionSupersededBy> DEC-NNN` (an edit, `formats.md § 6`; no CLI command swaps it). Status and Revisit when are the only cells of an old row that may change.
   - **Rejection of a recorded executor decision** (Origin `executor`, Status `vocab.decisionPending`): run `node "${CLAUDE_SKILL_DIR}/scripts/roadmap.mjs" reject "<folder>" DEC-NNN --decision "<the owner's decision>"` (optional `--discarded`, `--revisit`, `--what`). It adds a row of Origin `user` in force, sets the old Status to `<vocab.decisionSupersededBy> DEC-<new>`, drops the pending item and writes its own log row (skip step 4). Refusals `not-executor` (not an executor row) and `not-pending` (not pending) are exit 1: report them, change nothing.
3. Then whatever uses it: `state.md` (drop the pending item it resolves, adjust panel Next step and `now`; the strategy's Open questions entry stays until the next revision, § 9), `requirements.md` (a coverage change touching no card: `out-of-scope: <reason citing DEC-NNN>` or `needs-clarification`), `critical-path.md` (a changed gate, then refresh the next milestone per track, Common). A decision that forbids an action → also § 13. Card changes wait for the revision.
   - **A pending decision that affects a gate:** update the decision-trail row in `critical-path.md` and the panel Next step of the affected deliverables so both say the gate waits for that `DEC` (the checker does not detect it).
   - **A deliverable discarded** (the decision drops a card): panel Status `vocab.discardedStatus` (Common), Next step cites the DEC; the card keeps its place and gets priority `Won't` in the strategy **only after the revision is approved**; until then the approval `pending` item names the card ("(user) approve strategy v<N+1> (absorbs DEC-…; discards E<n>)"). Mark the node discarded in `critical-path.md`; remove gates only it held. Re-check REQ coverage (next bullet). The revision touches: overview of deliverables, phases (membership, exit criteria), non-goals (add what was dropped), coverage summary and the card (priority `Won't`, pieces and `reqs` kept as history); list them in the proposal (§ 9).
   - **A piece dropped or moved:** list the `REQ` that piece served (the card's `reqs` and the `requirements.md` rows whose Deliverables name that card) and re-check each one's coverage. Still served elsewhere → leave it and say so in the proposal. No longer served → set Coverage to `<vocab.coverageOutOfScope>: <reason citing DEC-NNN>` if the decision drops it from scope, otherwise `vocab.coverageNeedsClarification`; unclear which: ask (recommend `needs-clarification`). Card `reqs` change only in the revision.
4. `log.md`, only when no command wrote the row (not after `reject`): `node "${CLAUDE_SKILL_DIR}/scripts/roadmap.mjs" log "<folder>" --deliverable <E<n>|-> --what "DEC-NNN recorded: <short decision>" --evidence decisions.md`.

Checker: a filled Contradicts on an in-force decision → `contradiction-unabsorbed` (warning) until a revision cites the ID → propose one (§ 9). `superseded-link` if the superseding ID does not exist.
